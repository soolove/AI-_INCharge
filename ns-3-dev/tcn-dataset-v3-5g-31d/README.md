# tcn-dataset-v3-5g-31d

TCN 학습용 데이터셋이다. 2026-10-14에 v2 환경에서 만들었고, 시나리오당 31일이다. 이 폴더의 TCN(폭 64)은 이 데이터셋 하나로 학습했다.

- **저장소에는 이 README만 있다.** 데이터 파일(`tcn_dataset.npz`, `dataset_perminute.csv`, `sites.csv`, `rates.csv`, `antenna.csv`, 그림)은 아래 생성 명령으로 만든다.
- **재생성 확인 (2026-10-23)**: 지금 코드로 `--days 15`를 만들어 이 데이터셋의 0\~14일과 비교했다. `Mean_sinr_db`(무선 설정 차이)를 뺀 X 9채널과 Y가 모두 같았고, KPI1도 9.5%로 같았다.

## 생성 명령

```bash
python build_tcn_dataset.py --scenarios 일반일과 시험기간 축제 --days 31 --plot --outdir tcn-dataset-v3-5g-31d
```

- 나머지 인자는 기본값이다: seed 20250101, day-var 0.12, v2-conn-delay 3.0, activity 0.7, rate-cv 0.3, P_D 0.9, 720분.
- 로컬에서 만드는 데 8분 32초 걸린다.

## 생성 규칙

- **단위**: 5G 단위다(C_max 580 Mbps, 1인당 수요는 5G 이전 설계의 2.9배).
- **접속 지연**: 건물에 도착한 뒤 0\~6분 균등(평균 3분) 뒤에 접속한다.
  - 이전 데이터셋(`tcn-dataset-v2`, `tcn-dataset-v2-5g`)은 ns-3 시간 단위 버그로 0\~360분(평균 3시간)이었다.
- **선행 시차** (엔진 스펙 §6): 도착한 건물의 시차를 접속 지연 앞에 더한다. 강의동 5분, 도서관 2분, 기숙사 0분, 이벤트 12분이다.
- **09:00 재실자**: 그 시각에 막 도착한 것으로 본다(선행 시차 + 접속 지연 뒤 접속).
- **날 변동 시드**: `zlib.crc32(시나리오)`로 고정한다. 같은 명령이면 같은 데이터가 나오고, 0\~14일은 15일로 만들었을 때와 비트 단위로 같다.
- **무선 설정**: v2 무선 설정(3.5 GHz, 침투 손실 없음)에서 만들었다.
  - 이음5G 설정(4.77 GHz, 실내 침투 손실 16.2 dB)으로 다시 만들어도 TCN 입력 5채널(트래픽, UE 수, ISAC, 시각 sin/cos)은 똑같다. `Mean_sinr_db` 열만 평균 0.15 dB 낮아지며, 이 열은 TCN이 쓰지 않는다(../README_env.md 11-1절).
- **코드**
  - `scratch/cttc-nr-demo.cc`: 접속 지연, `lagMin` 적용
  - `build_tcn_dataset.py`: rates.csv의 `lagMin`, CRC 시드
  - `rl-env_v4/scenario_setup.py`: RL용 rates.csv의 `lagMin`

## 크기와 검증

- **크기**: `tcn_dataset.npz`는 X (1,083,078, 10, 60), Y (1,083,078, 15)다.
  - 93일(3 시나리오 x 31일) x 18셀 x 647개이고, 셀 1개당 시나리오당 20,057개다. NaN은 없다.
- **sha256**: `11c116f40a87262a066e7b017b59dab3c80aa45c3682ad41bb0abd23b374d126`. TCN 체크포인트 config의 `dataset_sha256`과 같다.
- **수요** (셀-분): 중앙값 25.8 Mbps, 상위 1% 549 Mbps, 최대 1,287 Mbps. U = D/580 > 0.8인 셀-분 2.00%.
- **재실 인원 중 접속 비율**: 09시 0.88, 10시 이후 0.94\~1.04 (같은 규칙의 15일판에서 확인).
- **유형별 접속 시작** (09:00 기준): 기숙사 0\~6분, 도서관 2\~8분, 강의동 5\~11분, 이벤트 12\~18분.
