# 이음5G 대시보드

**이음5G 환경**에서 만든 안테나 제어 대시보드다. 이음5G 환경은 반송파 4.77 GHz이고, 실내 단말에 건물 침투 손실 16.2 dB를 준다. 환경 설명은 [../README_env.md](../README_env.md)에, TCN과 에이전트 설명은 [../README_AI.md](../README_AI.md)에 있다.

- **파일 이름**: 결과물은 모두 `_이음5G`로 끝난다. v2 환경의 대시보드는 이 저장소에 넣지 않았다.
- **저장소에 있는 것**: 축제 시나리오의 영상·그림, 학습 그래프, 지도 배경(`data_이음5G/campus_bg.png`)만 있다. 하루 기록(`data_이음5G/<시나리오>/`)과 다른 시나리오의 영상·그림은 아래 "만든 방법"의 명령으로 만든다.
- **하루**: 시나리오 3개(일반일과, 시험기간, 축제) 각각 test 첫날(날 시드 200000), 09:00~21:00, 5분 step 144개
- **기법**: 상시 최대, 반응형(임계값 up 0.03 / down 0.02), 에이전트(PPO 보상 비율 1:10:5, 업데이트 760)
- **모델**: TCN(폭 64)과 에이전트는 v2 환경에서 학습한 것을 그대로 쓴다. 이음5G에서 다시 학습하지 않은 이유는 ../README_AI.md에 있다.
- **표시**: 영상과 그림 위쪽의 문구에 "이음5G 4.77 GHz"가 표시된다.

**npz 필드** (step k = 0..143)

| 필드 | 크기 | 단위 | 뜻 |
|---|---|---|---|
| `minute` | (144,) | 분 | step이 끝나는 시각, 09:00부터 경과 분 (5, 10, ..., 720) |
| `antenna` | (144, 18) | 개 | 그 5분 동안 셀별 활성 안테나 수 {2, 4, 8, 16} |
| `traffic_min` | (144, 18, 5) | Mbps | 그 5분의 분당 요구 트래픽 (셀별, 1분마다) |
| `forecast` | (144, 18, 16) | Mbps | step 시작 시각(= minute - 5)에 TCN이 낸 예측. `[..., 0:15]` = 1~15분 앞 중앙 예측, `[..., 15]` = 앞으로 15분의 피크 예측 |
| `ue` | (144, 18) | 명 | step 마지막 분의 셀별 접속 UE 수 |
| `outage_ue` | (144, 18) | 명 | step 마지막 분의 셀별 끊긴 UE 수 (끊김 = 모든 셀 반경 밖 또는 SINR < -5 dB, 가장 가까운 셀에 귀속) |
| `ho_in`, `ho_out` | (144, 18) | 회 | 그 5분 동안 셀로 들어온/나간 핸드오버 수 |
| `demand` | (144, 18) | Mbps·분 | 그 5분 동안 분당 요구 트래픽의 합 |
| `shortage` | (144, 18) | Mbps·분 | 그 5분 동안 처리하지 못한 트래픽의 합 (용량 초과분 + 끊긴 UE의 수요) |
| `energy` | (144,) | 상대값 | 그 5분 동안 캠퍼스 평균 전력, 상시 최대 = 1.0 (3GPP TR 38.864 모델, 고정분 0.3) |

예측 시각 맞추기: `forecast[k, c, h-1]`이 가리키는 시각은 `minute[k] - 5 + h`분이다 (h = 1..15).

**자주 쓰는 계산**
- 셀 용량 = 580 x `antenna` / 16 Mbps (72.5 / 145 / 290 / 580)
- 커버리지 반경: 안테나 2 / 4 / 8 / 16 = 40 / 55 / 70 / 85 m
- 전력 절감률 = 1 - mean(`energy`)
- QoS 부족 = sum(`shortage`) / sum(`demand`)

## 만든 방법

`ns-3-dev`에서 conda `smart_campus_5G` 환경으로 실행한다. ns-3 `cttc-nr-demo` 빌드가 필요하고, ns-3 기본값이 이음5G 설정이다.

```bash
# 1) 하루 데이터 수집 (9번을 동시에 돌리면 약 16초)
for sc in 일반일과 시험기간 축제; do for m in max reactive rl; do
  python dashboard/scripts/collect_day.py . dashboard/data_이음5G/$sc/day_$m.npz $m $sc 200000 "이음5G 4.77 GHz" &
done; done; wait

# 2) 그림·영상 (시나리오마다)
python dashboard/scripts/render_frame.py dashboard/data_이음5G/<시나리오> . out.mp4 09:00-21:00   # -> ffmpeg로 webm (vp9, 2 Mbps)
python dashboard/scripts/render_cells.py dashboard/data_이음5G/<시나리오> . <출력 폴더>
python dashboard/scripts/render_cell_videos.py dashboard/data_이음5G/<시나리오> . <출력 폴더> 1-18    # avg = 18개 셀 평균
python dashboard/scripts/plot_training.py . <출력 폴더>
```

- 사용 모델과 입력
  - TCN: `DGU_SC_Project/checkpoints/v3_5g_31d_w64_dual_proposal/seed_0_finetune/best.pt`, z 표준화 `rl-env_v4/z_stats.json`
  - 에이전트: `rl-env_v4/runs/ppo_v2_w64_r10/best.pt`, 반응형 임계값: `rl-env_v4/runs/reactive_tuned_v2_r10.json`
  - 시나리오 인원표: `../Scenario/<시나리오>.csv`, 사이트: `run_campaign.py`의 `SITES`
- `collect_day.py`는 기법마다 `day_<기법>.wp.csv`와 `day_<기법>.sites.csv`를 만든다. UE 이동과 사이트는 세 기법이 같아서, 그리는 스크립트는 `day_rl.wp.csv`만 쓴다.
- 그림·영상 스크립트는 기본 파일 이름(`cell_01.png` 등)으로 쓴다. 결과물은 만든 뒤 이름 끝에 `_이음5G`를 붙였다.
- 학습 그래프의 원자료는 `rl-env_v4/runs/ppo_v2_w64_r10/metrics.jsonl`과 `DGU_SC_Project/checkpoints/v3_5g_31d_w64_dual_proposal/seed_0_finetune/metrics.jsonl`이다.

**스크립트 복원 (2026-10-19)**
